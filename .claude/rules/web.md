# Web UI Rules

- Single-page app: stdlib `http.server`, vanilla JS, no build step, no npm
- HTML + CSS in `web/index.html`, JS in `web/js/*.js` (ES6 modules, `<script type="module">`)
- Route handlers in `web/routes/*.py` — server.py is the HTTP handler, the route dispatch tables, and `main()`; the process's state lives in `web/runtime.py`
- Beets queries via `lib/beets_db.py` `BeetsDB` class — never raw `sqlite3.connect()` in handlers
- MusicBrainz queries through local mirror at `http://192.168.1.35:5200` via `web/mb.py`
- Redis cache: `meta:` namespace only — pure MB/Discogs mirror metadata, 24h TTL via `memoize_meta` in `web/mb.py`/`web/discogs.py`. The routing-level response cache was REMOVED by #101 (it baked pipeline overlay state into cached responses); do not reintroduce response caching or reference `cache_api.cached(...)` — it no longer exists
- Static JS served at `/js/*.js` by server.py — `node --check web/js/*.js` must pass (pre-commit + CI)
- `// @ts-check` + JSDoc types on all exported functions; no inline `<script>` in HTML
- Pure functions in `web/js/util.js` — testable via Node without DOM; JS unit tests in `tests/test_js_util.mjs`, run with `node`, no npm
- **A `web/js` module exports names, never a test bag** (#1313). A helper a suite needs is `export function foo(...)` at its declaration, with its JSDoc. The retired `export const __test__ = {…}` convention listed 137 names across seven modules: 56 were already named exports, listed a second time; 19 turned out to have no reader anywhere and are no longer exported at all; four it renamed on the way out, so production and tests spelled one function two ways. `tests/test_js_suite_audit.py::TestNoModuleShipsATestBag` refuses it in any spelling, on both sides. Leave a helper unexported when nothing outside its module reads it. Nothing enforces that, and the #1313 residual sweep declined to build the enforcement: a correct reader check would need three grammars, because 5 of the 12 candidates it measured are live only through a Python generated test naming the export as a string for its Node worker (`tests/test_long_tail_cache_lifecycle_generated.py`, `tests/test_protected_path_truth_generated.py`), and growing a checker one grammar at a time is what § "Semantic source scanners are prohibited" forbids. The sweep instead un-exported the seven that genuinely had no reader anywhere, so the count starts from zero and the next one shows up in a diff
- **Every `tests/test_js_*.mjs` suite uses the one shared harness, `tests/js_harness.mjs`** (#1313): `const t = suite(import.meta.url);`, then `t.section(label)` headers and `t.ok/equal/notEqual/deepEqual/contains/excludes/match/notMatch/throws/rejects/fail/pass(...)`, ending in exactly one `t.done();`. Every assertion needs a message — it becomes the failure's identity (`<file>::<section>::<message>`) in the suite's failure index, and the harness fails closed on an unnamed one. `contains`/`excludes` take a STRING haystack and refuse anything else, because the `String(haystack)` coercion they used to do inverts an array (`['ab','cd'].includes('a')` is false, `String(['ab','cd']).includes('a')` is true); an array site keeps `t.ok(x.includes(y), …)`. Stub browser globals with `stubGlobals({document, window, fetch})` and build a `document` with `domStub(elementsById, extra?)` / `element(seed?)`, rather than hand-writing the save-assign-restore dance. **The harness owns the restore and the section is the scope** (#1346): a stub installed after a `t.section(...)` is handed back at the next one, the last section's at `t.done()`, and one installed before the first section is the file's baseline world and lives until `done()`. Call the returned `restore()` only when a block wants its world back sooner; calling it twice is a no-op. A bare `globalThis.fetch = …` opts out of all of that silently — the stub survives every later section, so a section that installs no `fetch` of its own answers from whichever mock ran last. 104 sites were in exactly that state, `test_js_browse.mjs` and `test_js_pipeline.mjs` with no restore of any kind; `tests/test_js_suite_audit.py::TestNoSuiteMutatesAGlobalWithoutRestoringIt` now refuses the shape, in every spelling including `globalThis['fetch']` and the node `global` alias. `element()` covers what the suites used to hand-roll: attributes behind `setAttribute`/`getAttribute`/`hasAttribute` (never as fields, so an attribute cannot clobber a method), plus `isConnected`, `children`/`appendChild`, `focus()`/`focused` and `remove()`. A fresh node is disconnected, as in a real DOM; seed `isConnected: true` for one that stands in for something already on the page, and read attributes back through `getAttribute`, not through the map. Do not hand-roll `passed`/`failed` counters or import `node:assert` — `tests/test_js_suite_audit.py` rejects both
- **A suite drives the composed entry its module actually exposes, and calls leaves directly for their own HTML** (#1346). The two answer different questions and neither replaces the other: a leaf call asserts the fragment it produces, and only the entry can prove the composition — the order of the fragments, which payload field feeds each one, and what the entry derives on the way. `toggleDetail` composes nine fragments and every one of `test_js_pipeline.mjs`'s row assertions passed with `data.current_library` swapped for `data.request`, which is the whole point. Drive the entry with sentinels unique to the field each proves, assert their ORDER, and slice per fragment where a needle could match a neighbour (`renderPipelineDashboard`'s composer test is the pattern). Where a suite deliberately does not drive an available entry, the suite's own header says why — `tests/test_js_recents.mjs` (the payload-contract audit reads the literal argument at the direct call site), `tests/test_js_util.mjs` (the entries are driven in the suites that own them) and `tests/test_js_discography.mjs` (the renderers are not leaves of that entry) are the worked examples
- Shared state in `web/js/state.js` — no bare globals across modules; cross-module onclick handlers go through `window.*` bindings in `main.js`
- Route functions take `(handler, params)` or `(handler, body)`, not `self`; route modules read the process's collaborators from the frozen `web/runtime.py::WebRuntime` via `runtime()` (a module-scope import — the old `_server()` deferred-import shim is gone with the cycle it dodged). `web/server.py` builds and installs one at startup; tests install their own with `install_runtime`. The one surviving deferred `from web import server` is `web/routes/api_index.py`, which reads the import-time `ALL_ROUTES` registry rather than runtime state
- Fetch-on-input UI must stamp requests with a module-scoped in-flight token and discard stale responses before rendering
- The web UI reads download_log JSONB columns (import_result, validation_result) — use the typed field names from the dataclasses, not arbitrary strings
- **Visible UI changes are verified with the dev-server screenshot loop BEFORE pushing** — live-db dev server + CDP chromium + playwright agent, and the main agent Reads the PNGs itself. Tests+review alone shipped three visually-obvious defects on #575. Full recipe + gotchas: `docs/solutions/ui-dev-server-screenshot-loop.md`
- After changes: `ssh doc2 'sudo systemctl restart cratedigger-web'`
